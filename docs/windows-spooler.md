# Спулер Windows: что выяснено на живом парке

Разбор проводился на Windows 10 (build 19043) с пятнадцатью принтерами Epson трёх
разных драйверов. Всё ниже — не теория из документации, а результат прогонов;
там, где поведение расходится с ожидаемым, указано, как проверялось.

Читать до правок `electron/main/spool.ts`.

## 1. Спул-файл нельзя найти перебором каталога

Задания лежат в `%SystemRoot%\System32\spool\PRINTERS` парами `FP00204.SPL` +
`FP00204.SHD`. Имя файла содержит **счётчик спулера, а не номер задания**:
`FP00152.SPL` может принадлежать заданию 166. Опознать пару можно только по
содержимому `.SHD` — там лежат номер задания, имя принтера и имя документа.

**Так не выйдет: `.SHD` открыть невозможно.** Спулер держит его монопольно.

```
FP00204.SHD share='ReadWrite'          -> IOException
FP00204.SHD share='ReadWrite, Delete'  -> IOException
FP00204.SHD share='Read, Write, Delete'-> IOException
FP00204.SPL share='ReadWrite'          -> ok
```

Ни один режим совместного доступа не помогает. Именно на этом полгода не работал
перенос: код ловил `IOException` и молча пропускал кандидата, поэтому в журнале
оказывалось «кандидаты: нет» при том, что рядом лежали живые `.SPL`.

Вывод: **каталог со спул-файлами читать не нужно вообще.**

## 2. Данные задания отдаёт сам спулер

Документированный способ: `OpenPrinter` принимает имя вида `"Принтер, Job 217"`
и возвращает хэндл задания, из которого `ReadPrinter` читает спул целиком.

Ключевая тонкость — права. Матрица прогона по заданию 217:

| `DesiredAccess` | Результат |
|---|---|
| `PRINTER_DEFAULTS = NULL` | **READ total=22616** ✅ |
| `0x0` | READ total=22616 ✅ |
| `0x4` ADMINISTER | open err 5 |
| `0x8` USE | open err 5 |
| `0xF000C` ALL_ACCESS | open err 5 |
| `0x10`, `0x20` | открывается, но читает 0 байт |

То есть хэндл **задания** открывается только с нулевыми `PRINTER_DEFAULTS`.
Интуитивный `PRINTER_ACCESS_USE` даёт ACCESS_DENIED.

Прочитанный размер совпадает с `Size` из `Get-PrintJob` и с длиной `.SPL`.

## 3. `SetJob` уровня 1 требует ADMINISTER

`AddJob` заводит задание на приёмнике **всегда как `RAW`** и с именем документа
«Удалённый документ прежних версий». Исправляется `SetJob` уровня 1, но он
требует прав на **хэндле принтера**:

| `DesiredAccess` принтера | `SetJob` уровня 1 |
|---|---|
| `NULL` / `0x0` | set=False, err=5 |
| `0x8` USE | set=False, err=5 |
| `0x4` ADMINISTER | **set=True** ✅ |
| `0xC` ADMIN\|USE | **set=True** ✅ |

Ошибка коварна: `SetJob` возвращает булево, его легко не проверить, а результат —
EMF, расписанный как RAW, то есть пачка мусора на бумаге. Поэтому в коде неудача
`SetJob` **отменяет перенос**, а не продолжает его.

Обратите внимание: `AddJob` требует `USE`, `SetJob` — `ADMINISTER`. Открывать
надо с обоими (`0xC`), с откатом на обычный хэндл, если прав не дали.

## 4. Побайтовая копия привязана к драйверу

Спул бывает двух видов, и это определяет, что вообще возможно:

- **`NT EMF 1.00x`** — контейнер EMFSPOOL с готовым EMF на каждую страницу. EMF
  аппаратно-независим, но сам контейнер несёт `DEVMODE` источника.
- **`RAW`** — уже собранный код конкретной модели (ESC/P2 у Epson, PCL, PostScript).

Скопировать байты и подсунуть другому принтеру можно только при **общем
драйвере**. Перегнать ESC/P2 в PCL без растеризатора нельзя — это не вопрос
реализации.

## 5. Перенос между любыми принтерами — через перерисовку

EMF на то и векторный, что его можно проиграть в контекст любого устройства.
Спулер при печати делает ровно это.

Алгоритм:

1. Прочитать спул (см. §2).
2. Разобрать контейнер EMFSPOOL на страницы.
3. `CreateDC` на целевой принтер.
4. `StartDoc` → на каждую страницу `SetEnhMetaFileBits` + `StartPage` +
   `PlayEnhMetaFile` + `EndPage` → `EndDoc`.
5. Удалить исходное задание.

Проверено переносами: Epson L8050 → Epson L8050, Epson L8050 → **Epson L805**
(другой драйвер), Epson L8050 → **Microsoft Print to PDF** (совсем посторонний
драйвер). В последнем случае результат скачан и просмотрен — содержимое совпадает
один в один.

### Формат контейнера EMFSPOOL

Заголовок, затем записи парами `(ulID, cjSize)`, выровненные на 4 байта:

```
0x00  DWORD dwVersion   = 0x00010000
0x04  DWORD cjSize      = 0x24 (36) — с этого смещения идут записи
```

Реальный разбор задания на 22616 байт:

```
hdr version=0x00010000 size=36
  rec id=0x0C size=14356  emrType=1 sig=0x464D4520 [EMF]   <- страница
  rec id=0x03 size=8192                                     <- DEVMODE источника
  rec id=0x0E size=8
emf blobs=1
```

Значимые `ulID`: `0x01`/`0x0C` — метафайл страницы, `0x03` — `DEVMODE`,
`0x0D`/`0x0E` — «расширенные» варианты, у которых телу предшествует ещё DWORD
смещения.

Надёжнее не доверять номеру записи, а проверять сигнатуру: тело — это EMF, если
по нему `iType == 1` и на смещении 40 лежит `" EMF"` (`0x464D4520`). Длина берётся
из `nBytes` заголовка EMR — это **смещение 48**, не 44 (на 44 лежит `nVersion`).

### Перенос `DEVMODE`

Целиком `DEVMODE` источника тащить нельзя — он про чужое устройство. Берётся
`DEVMODE` получателя через `DocumentProperties`, и в него переносятся только
устройство-независимые поля, если источник объявил их в `dmFields`:

| Смещение | Поле | Бит `dmFields` |
|---|---|---|
| 76 | `dmOrientation` | 0x1 |
| 78 | `dmPaperSize` | 0x2 |
| 80 | `dmPaperLength` | 0x4 |
| 82 | `dmPaperWidth` | 0x8 |
| 86 | `dmCopies` | 0x100 |
| 92 | `dmColor` | 0x800 |
| 94 | `dmDuplex` | 0x1000 |

Затем результат прогоняется через `DocumentProperties` с
`DM_IN_BUFFER | DM_OUT_BUFFER`, чтобы драйвер сам выкинул то, чего не умеет.

Метафайл кладётся на `HORZRES`×`VERTRES` получателя, то есть задание
подстраивается под его бумагу, а не тащит геометрию источника.

## 6. Статусы задания

Встречались в журналах, полезно при разборе:

| Значение | Смысл |
|---|---|
| `0x0` | в очереди, спул дописан |
| `0x1` | на паузе |
| `0x8` | **спулится**, размер ещё 0 |
| `0x10` | печатается |
| `0x2010` | печатается + сохранено после печати |

Пока стоит `0x8`, читать нечего. Крупный кадр из Lightroom (16 МБ) пишется
несколько секунд — приложение ждёт до 15 с.

## 7. У системного задания нет пути к файлу

Спулер хранит только **имя документа**. Задание, отправленное из чужой программы
(`Lightroom (_MG_0114.CR2)`), связать с файлом на диске неоткуда — ни миниатюры,
ни предпросмотра.

Обходится только для того, что отправило само приложение: `origins.ts` запоминает
путь при печати и потом узнаёт задание по имени документа. Сопоставление идёт по
имени без расширения и без привязки к принтеру — перенос заводит на приёмнике
новое задание, и снимок должен переехать вместе с ним.

## 8. Разное

- Перенос требует, чтобы у принтера была **включена очередь** и сохранение
  документов после печати. Без этого читать нечего — приложение предлагает
  «Разрешить перенос», это `enableSpooling()`.
- В `PRINTERS` встречаются подкаталоги с однобуквенными именами (`1`…`e`) и
  временные `DSP*.tmp` — к заданиям отношения не имеют.
- SSH-сессия Windows OpenSSH под учётной записью администратора получает
  **повышенный** токен (`S-1-16-12288`), то есть годится для отладки спулера.
- `nativeImage` не читает RAW-форматы камер (`.CR2`) и PDF — возвращает пустое
  изображение, это нормальный путь, а не ошибка.
