# Работа над этим проектом

Электрон-приложение: очередь печати Windows. Пользовательская документация — в
[README.md](README.md), она описывает готовый продукт. Здесь — то, что нужно
знать, чтобы его менять.

## Язык

Комментарии в коде, сообщения коммитов, тексты интерфейса и общение —
**по-русски**. В старом коде местами остались английские комментарии; переписывать
их специально не нужно, но новые пишутся по-русски.

Комментарий объясняет **почему**, а не что. Хороший образец — заголовки файлов
`electron/main/spool.ts` и `electron/main/origins.ts`: там записано, какой подход
был отвергнут и по какой причине. Это спасает от повторного захода в те же грабли.

## Устройство

```
electron/main/       главный процесс
  index.ts           точка входа, окно, регистрация IPC, протокол pq-file://
  manager.ts         состояние приложения, слияние системных и эмулированных очередей
  windows-source.ts  чтение спулера, печать файла, действия над принтером
  spool.ts           перенос задания между принтерами (самое сложное место)
  origins.ts         связь системного задания с исходным файлом
  preview.ts         предпросмотр и миниатюры
  powershell.ts      запуск PowerShell, разбор JSON
  watcher.ts         опрос спулера
  simulator.ts       эмуляция парка принтеров
  store.ts           настройки на диске
electron/preload/    мост contextBridge, единственный список доступных API
shared/              типы и имена IPC-каналов, общие для процессов
src/                 интерфейс на React
tools/               диагностические скрипты для запуска на самой машине
docs/windows-spooler.md   разобранное поведение спулера Windows — читать до правок spool.ts
```

Взаимодействие с Windows идёт **через PowerShell**, а тяжёлые вещи — через
`Add-Type` с C# и вызовами `winspool.drv` / `gdi32.dll`. Нативных зависимостей у
проекта нет и заводить их не надо: сборка должна оставаться чистой.

## Правила, выведенные из граблей

Каждое здесь стоило отдельного разбора. Нарушение любого из них уже приводило к
багу, который выглядел как «просто не работает».

### PowerShell

1. **Скрипт с кириллицей передаётся файлом с BOM.** PowerShell 5.1 читает `.ps1`
   без BOM как ANSI и ломается на первой русской букве. Внутри приложения для
   этого есть `psJsonFile()`; скрипты в `tools/` сохранены с BOM.
2. **Длинный скрипт нельзя передавать аргументом.** Командная строка Windows
   обрывается на 32767 символах. Помощник переноса заданий занимает больше
   двадцати тысяч — только `psJsonFile()`, только `-File`.
3. Имена принтеров содержат кавычки и скобки — экранировать через `psq()`.
4. У `psJson()` вывод парсится как JSON целиком, поэтому в скрипте не должно быть
   ничего лишнего в stdout.

### Спулер

5. **`.SHD` рядом со спул-файлом открыть нельзя** — спулер держит его монопольно,
   при любом режиме доступа. Искать задание перебором каталога
   `System32\spool\PRINTERS` бесполезно; это был исходный баг переноса.
6. **Данные задания берутся у спулера**: `OpenPrinter("Принтер, Job N")` +
   `ReadPrinter`. Хэндл задания открывается **только с нулевыми
   `PRINTER_DEFAULTS`** — с `PRINTER_ACCESS_USE` спулер отвечает ACCESS_DENIED.
7. **`SetJob` уровня 1 требует `PRINTER_ACCESS_ADMINISTER`.** Без него он молча
   возвращает ошибку 5, тип данных остаётся `RAW`, и EMF уезжает на бумагу
   мусором. Ошибку легко не заметить — результат возвращается булевым.
8. **Побайтовая копия спула привязана к драйверу.** Переносить между разными
   моделями можно только перерисовкой: разобрать контейнер EMFSPOOL на страницы
   и проиграть их `PlayEnhMetaFile` в DC получателя.
9. Задание надо **дождаться**: пока статус содержит `JOB_STATUS_SPOOLING`,
   `ReadPrinter` отдаст обрезок. Крупная печать из Lightroom пишется секунды.
10. Задание, **уже стоявшее на паузе**, после неудачного переноса разжимать
    нельзя — иначе оно уедет печататься на старый принтер.

### Интерфейс

11. **Оптимистичная раскладка снимается только по подтверждению сервера.**
    Опрос очереди идёт не в такт с переносом, и сброс сразу возвращал задание в
    старый блок на секунду. Признак переезда: задание либо на целевом принтере,
    либо исчезло — перенос заводит на приёмнике **новый номер**, а старый удаляет.
12. **Из перетаскивания окна исключается только то, что само ловит мышь.**
    Правило вида `.chrome > *` убивает перетаскивание целиком, потому что под него
    попадает растянутый на всю ширину спейсер.
13. **Исходник картинки в интерфейс не отдаётся.** В фотоочереди это десятки
    мегабайт на строку ради шестнадцати пикселей. Миниатюру готовит `nativeImage`
    в главном процессе.

### Проверка

14. **Проверять на живой машине, а не рассуждением.** Всё, что здесь описано,
    выяснено прогоном на реальном парке принтеров. Для этого есть `tools/`.
15. **Контрольный прогон обязателен.** Если тест проходит после правки — прогнать
    его же на старой сборке и убедиться, что он падал. Иначе неизвестно, что
    именно проверено. Так проверялось перетаскивание окна: старая сборка давала
    сдвиг `0,0`, новая — `83,65`.

## Сборка и выкладка

```
npm run typecheck     проверка типов, обе конфигурации
npm run build         vite: интерфейс и оба процесса Electron
npm run dist          установщик NSIS и zip в release/
npm start             сборка и запуск
```

Приложению нужны **права администратора** (`requireAdministrator` в
`package.json`): без них не работает правка чужих заданий.

### Быстрая выкладка без релиза

Для проверки на месте не нужен установщик: всё приложение лежит в одном
`app.asar`, его можно подменить.

```powershell
npm run build
npx electron-builder --win --dir --x64 --publish never
.\tools\pq-deploy.ps1        # остановит приложение, подменит app.asar, поднимет обратно
```

Целостность asar в exe не проверяется, подмена одного файла работает.
`pq-deploy.ps1` сам делает резервную копию рядом.

### Релиз

Собирает **GitHub Actions по пушу тега** — руками ничего заливать не надо:

```
npm version <версия> --no-git-tag-version   # либо правка package.json
git commit -am "..."
git tag -a v<версия> -m "..."
git push origin main --tags
```

Через ~3 минуты в Releases появятся `setup.exe`, `.blockmap`, `.zip` и
`latest.yml`. **`latest.yml` обязателен** — по нему установленные копии видят
обновление.
